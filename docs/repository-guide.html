Data-Berge OS / newcomer map

Understand the product before changing the code.

Data-Berge OS is a multi-tenant analytics workspace. People upload files or connect a remote database, explore governed data, ask questions, create charts, and generate reports.

1 / The map

One product, two main applications

frontend/

What the user sees

React + TypeScript user interface. It owns screens, browser routing, API calls, visualizations, and session state.

backend/

What does the work

FastAPI service and background worker. It owns authentication, tenant checks, file processing, data queries, connectors, reports, and storage access.

docs/ · deploy/ · tests/

How it operates

Architecture and runbooks, deployment references, and load tests. These explain and validate the running product rather than deliver features directly.

2 / A normal browser request

Follow one request end to end

BrowserA user opens the workspace.
ReactApp.tsx selects the screen.
API clientservices/api.ts calls /api.
FastAPI routeapp/api/ validates the request.
Workflow + storageBusiness work runs and responds.

The frontend entry points

frontend/src/main.tsx boots React. App.tsx decides which page to show. routing/useAppRoute.ts owns browser history. contexts/AuthContext.tsx keeps the signed-in user available.

The backend entry point

backend/app/main.py creates FastAPI, installs middleware, exposes health checks, and attaches each API router.

Useful mental model: a route should be thin. It accepts HTTP input and enforces access. A workflow coordinates the use case. Services and repositories do the specific technical work.

3 / Data, analysis, and background jobs

There are two types of data source

Materialized sources: files and OpenDOSM

CSV and Excel uploads, plus downloaded OpenDOSM data, become local working data for DuckDB-backed analysis. In production, original and generated files belong in object storage.

Upload / download→Profile→Object storage→DuckDB query

Federated sources: Supabase

The selected PostgreSQL table stays remote. The app stores encrypted connection metadata and sends bounded, read-only queries only when needed.

Why a worker exists

Report generation and connector operations can take longer than a normal web request. The API puts jobs into Redis; backend/scripts/worker.py consumes them. PostgreSQL tracks durable job state, while Redis coordinates queued work.

API route→Redis queue→Worker→Report / connector work→PostgreSQL + S3

5 / Local development

Choose the smallest useful way to run it

Full stack

Use this when testing production-like behavior: PostgreSQL, Redis queues, S3-compatible object storage, migrations, API, worker, and frontend.

docker compose up -d
docker compose ps

Frontend only

Use this for UI work while the backend is already running.

cd frontend
npm ci
npm run dev

Before handing off a change

cd frontend
npm run test:run
npm run build

cd ..\backend
.venv\Scripts\python.exe -m compileall -q app data_berge_core scripts
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m pip check

7 / Local files

Know what is source code and what is disposable

Usually safe to regenerate

backend/.venv/, frontend/node_modules/, frontend/dist/, .pytest_cache/, and Python __pycache__/ folders are local dependencies or build/test output. They are intentionally ignored by Git.

Do not remove casually

data/app.db and data/uploads/ hold local product data. Removing them resets the local application and deletes local uploads.

Rule of thumb: if a file is tracked by Git, treat it as project content. If it is ignored, decide whether it is disposable output or local data before deleting it.

A calm return path

If you have not touched the repo for a while

  1. Read README.md and docs/ARCHITECTURE.md.
  2. Run git status before changing anything; understand existing local changes first.
  3. Run the frontend and follow one workflow: upload a file → inspect its profile → ask a question.
  4. Open the matching frontend component, API route, workflow, and test for that feature.
  5. Make one focused change and run the verification commands in this guide.
